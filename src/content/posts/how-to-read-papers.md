论文的产量已经超出任何人类的阅读能力：arXiv cs.CL 每月新增数千篇，加上技术报告与博客，全职阅读也只能覆盖千分之一。所以读论文的第一个原则是：**承认你是在做投资组合管理，不是在做藏书**。这篇短文记录我目前稳定的流程，也作为本站「论文精读」栏目每篇笔记背后的模板说明。

## 三层过滤

**第一层：标题 + 摘要 + 图表（约 3 分钟）**。回答两个问题：这篇文章解决的是真问题还是自造问题？它的证据强度是什么量级（理论证明 / 大规模实验 / 消融完整 / 只有 demo）？绝大多数论文在这一层出局——出局不是差评，只是与当前的问题意识不匹配。

**第二层：引言 + 方法图 + 实验设置（约 30 分钟）**。目标只有一个：能不能用自己的话复述「它做了什么改动、在什么基准上、和谁比、赢了多少」。复述不出来就说明要么没读懂，要么作者没讲清楚——两种情况都值得记一笔。这一层通过的文章才进入正式笔记。

**第三层：全文精读 + 复现关键数字（数小时）**。只留给两类文章：定义了新范式的基础工作（Transformer、Scaling Laws 这个级别），或与我正在写的问题直接相关的工作。精读的标志不是「看完了」，而是能回答下面四个固定问题。

## 四个固定问题

每篇精读笔记我都会强迫自己回答：

1. **它解决什么问题，且这个问题为什么在它之前解决不了？**——如果答不出「之前为什么不行」，大概率没理解创新点，或者创新点是伪的。
2. **方法的哪个部件承载了主要收益？**——好的论文有消融实验替你回答；没有消融的论文，你要在脑内做消融，并对结论的可信度降权。
3. **结论的边界在哪里？**规模区间、领域、语言、数据分布。默认所有结论都是局部的，「通用」是营销词。
4. **如果我是审稿人，我最想攻击哪一点？**——这一条催生了每篇笔记里的「批判性评价」小节。它防止精读变成抄写。

## 为什么批判性评价是必填项

不带批判的精读会制造一种幻觉：你「读过」一百篇论文，于是觉得自己了解领域。但知识分两种——知道结论，和知道结论的脆弱程度。后者只能通过主动挑刺获得。而且批判是双向的：很多经典论文的伟大之处，恰恰在于它对某个流行观念的攻击（「Attention is All You Need」本身就是对 RNN 时代的一次攻击）。

一个实用技巧：给每篇论文的批判性评价先写「最弱的一环」，再写「它依然重要的理由」。先攻击后辩护的顺序很重要——反过来写容易变成总结陈词。

## 沉淀格式

本站的论文精读模板由这几部分构成：一句话总结（oneLiner）、要点（takeaways，三条以内）、以及正文的固定七段——「背景 / 动机 / 方法 / 实验设置 / 结果 / 有趣的洞见 / 批判性评价」。七段分别回答：这篇论文之前世界什么样、作者赌了什么、具体怎么做、在什么条件下验证、数字说明了什么、哪里最值得怀疑。结构固定，跨论文才可比。

最后一条经验：**读论文的复利来自写，不来自读**。三个月后你能记住的不是读过的论文，而是写过笔记的论文。这也是这个网站存在的理由。
